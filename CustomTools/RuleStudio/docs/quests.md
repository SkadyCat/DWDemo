# 首层引导任务

Opus Studio 5291 的游戏内任务系统，当前只有「初入高塔」。

- 新玩家沿用现有普通 T1 霜棘法杖，第一技能槽自动装配冰锥术，不额外复制技能或赠送其他装备。
- 左上角任务卡显示目标与当前波次。点击任务卡、右侧任务图标，或按 J 打开任务窗口。
- 任务窗口沿用战斗窗口样式，提供移动、施法、三波怪物和首领的引导；打开暂停，关闭恢复此前暂停状态。
- 第一层实际清完三波并击败守卫后完成。失败、进入层数、普通击杀、其他层通关均不算完成。
- 完成后弹出三把随机武器，选择其中一把放入背包，不自动替换当前武器。未选择前可以关闭窗口，之后继续领取。

## 上层结构

`public/quests/model.mjs` 保存任务定义、进度、奖励生成和一次领取事务；`panel.mjs` 与 `style.css` 只负责表现。

任务进度放在现有玩家存档的 `quests` 字段，状态为 `active → reward → claimed`。候选武器在首次通关时生成一次并完整保存；重开页面、重复挑战或停留结算帧不会重抽。领取会把所选的原实例放入背包，记录已领取，其余两件不进入背包。已有存档只补任务字段，不清空装备或天赋；重置玩家时任务随新存档重置。

候选复用 `public/equipment-generation.mjs` 的正常掉落生成器，将部位池限定为武器，三个不同底材，首层奖励为 T1。品质概率、词条数量、前后缀、部位约束、固定基底和传奇词条全部沿用现有生成规则。

`battle3d.mjs` 观察 `DungeonBattle` 的通关结果，在切换层数前结算任务。任务数据不进入技能聚合、修饰器或规则世界，不改变伤害、血量和首领判定。

## 验证

`node --test tests/quests.test.mjs` 覆盖初始技能、旧存档补齐、完成条件、武器池与阶级、固定候选、刷新恢复、只领取一件、错误原子性，以及实际三波和首领战斗的通关结果。

浏览器验证脚本与截图在 `G:/DungeonWorldOpus/Saved/QuestSystem/`。验证使用独立存档；确认冰锥术开局、任务引导、真实首层胜利、三把武器显示、领取前后刷新、精确领取原实例及窄窗口无横向溢出。
